01

What is VirtuWill?

The problem it solves

Most personal websites are static pages maintained like chores. VirtuWill is a living personal operating system — a single authenticated Flask application where one admin password unlocks a private journal, a garden planner, music upload tools, and full portfolio management, while the public sees a clean curated face.

The design principle: visitors get a polished portfolio; the owner gets a full tool. The same URL serves both audiences dynamically based on session state.

  • No CMS, no Squarespace — everything hand-built and owned
  • Zero client-side build step — modules load as plain script tags
  • Flask backend handles auth, file uploads, and persistent JSON stores
  • Admin features toggle on/off globally via one 🐙 octopus button in the footer

Who it's for

Built by Will Yoste, Enterprise Data Product Owner at Greystar Real Estate Partners. The app reflects the same philosophy Will applies to data platforms: systems should be purposeful, maintainable, and actually used — not just built and abandoned.

VirtuWill documents Will's life across four dimensions:

  • Professional — resume, portfolio, project walkthroughs
  • Creative — original music catalog, guitar tabs, lyrics
  • Garden — aerial-mapped planner, photo gallery by bed and plant
  • Personal — private journal, travel map, daily habit tracking

Nine modules, one SPA

🎵
Music
Real HTML5 audio playback — not mocked. Four sub-sections: a song catalog with admin upload (mp3/wav), a photo gallery, streaming links to Spotify/YouTube/Apple Music, and a Tabs & Lyrics accordion per song. Floating mini-player persists across navigation and is draggable along the bottom edge.
Admin upload · Real audio
⚙️
Garden Planner
Canvas-based garden CAD tool on a calibrated 80×120 ft lot map. Beds defined as polygon, rectangle, or circle shapes in world-space feet. Plants snap to a 0.25 ft grid inside each bed. Free-draw tool with Ramer–Douglas–Peucker path simplification. Beds drag independently, vertices reshape, plants swap on drop.
Canvas · World coords · Free draw
🌿
Garden Gallery
Public photo gallery separate from the admin planner. Photos tagged with multiple bed IDs and plant species. Three grouping modes: By Bed, By Plant, All Photos. Collapsible sections, full-screen lightbox, admin upload modal. Quote/note block at top with inline editing.
Multi-tag · Collapsible · Lightbox
✈️
Travel Map
Leaflet.js on OpenStreetMap — no API key. Admin can place emoji pins (visited/recommend/wishlist), drag to reposition, and type country or US state names to shade them on the GeoJSON world map. Photos overlay as thumbnail markers. Google My Maps iframe embed support.
Leaflet · GeoJSON shading · Draggable pins
📄
Resume & Portfolio
Stylized resume derived from Will's actual PDF — four tabs (Ethos, Experience, Skills, Education) with a professional persona section at top. Portfolio grid with admin toggle/delete controls. Supports HTML file upload for new projects — each uploaded file renders as a card and opens in a full iframe.
PDF download · HTML upload · iframe
📓
Private Journal
Session-authenticated private journal with collapsible year/month timeline. Each entry supports a quote, meal log (B/L/D), free-write, and seven daily habit toggles: Run, Lift Weights, Play Guitar, Sexual, Drinking, Smoking, Reading. Full CRUD with photo OCR upload.
Auth-gated · Habit toggles · CRUD
✉️
Contact Form
Visitor-facing note form: name, optional contact method (email/phone/socials), and message body. Submissions saved server-side to a JSON store. Admin inbox view with unread highlighting and mark-read actions — visible only when signed in.
Server-stored · Admin inbox
🔐
Unified Admin System
One password via the discreet 🐙 footer icon unlocks the journal, garden planner, music upload, portfolio management, contact inbox, and garden gallery admin tools simultaneously. Green admin banner signals active session. Single sign-out returns to visitor view globally.
Flask sessions · Global admin state
💬
Chat with Will
Floating chat agent powered by a local LLaVA model via Ollama. Persona-grounded with a Q&A interview style context file aligned to Will's actual experiences and opinions. Chat UI embeddable as an iframe. Thread-managed with conversation history stored as local logs.
LLaVA · Ollama · Persona-grounded
03

Architecture

Frontend — Vanilla JS modules
window.VW namespace Each module (Music, Journal, Resume, Travel, Contact) registers on window.VW. No bundler, no npm. Loaded as plain <script> tags in dependency order.
app.js router SPA routing via go(page). ALL_PAGES array controls visibility. Handles admin auth state and broadcasts changes to all modules.
Canvas planner garden.js manages a world-coordinate geometry system (feet) with a camera transform. All rendering via ctx.scale/translate — no SVG, no library.
Leaflet.js map Only external JS library used in production. GeoJSON country/state shading loaded from CDN, cached by browser.
Backend — Flask + Python
Session-based auth Flask sessions gate the admin and journal endpoints. Single ADMIN_PASSWORD in config.py, default virtuwill2026. Journal has its own session key.
JSON file stores data/garden.json, data/messages.json, data/music_catalog.json, data/portfolio_uploads.json. No database required for personal-scale use.
Static file serving Audio uploads → static/audio/. Portfolio HTML → static/portfolio/. Garden photos → API endpoint with server-side save.
Flask-native template Single Jinja2 template (index.html, 1,372 lines) hosts all page divs. Page routing is CSS display toggling, not server-side page changes.
Storage strategy
Server-side (Flask) Garden planner layout, journal entries, contact messages, music catalog, portfolio uploads. Survives page reload, accessible on any device.
localStorage (browser) Travel pins, visited countries/states, portfolio visibility state, garden gallery photos, garden hero quote. Fast access, session-persistent.
Blob URLs (session only) Photo uploads shown immediately via URL.createObjectURL(). Server upload attempted in background; blob stripped before JSON persistence.

05

Engineering challenges solved

01 Bed editor: other beds disappearing
When entering bed edit mode, all other beds vanished. Root cause: the vignette used destination-out composite which erased the alpha of previously drawn bed polygons.
Fixed by strict render layer order: satellite → other beds (dimmed) → vignette → active bed. Other beds are drawn before the vignette is applied so they survive the composite operation.
02 Bed drag: shapes jumping on mousedown
Dragging a bed caused it to teleport on the first frame. The delta calculation incorrectly subtracted the polygon centroid from the movement vector.
Fixed to track dragBedOffset as the raw world cursor position. Each frame: ddx = w.x − dragBedOffset.x, then update dragBedOffset = w. Simple incremental delta, no centroid involved.
03 Garden planner: plant coordinate drift
Moving a bed left plants behind at their original world coordinates. The plant x/y were absolute world positions, not relative to the bed.
Rewrote to store plants as grid indices (gi, gj) in bed-local space. plantLocalPos(plant, bed) converts back to world via the bed transform. Move the bed transform, plants move for free.
04 Vertex hit testing: too small at low zoom
Polygon vertex handles were nearly impossible to grab at low zoom. Hit radius was 1.5 world feet — fine at 20× zoom but invisible at 2×.
Changed hit radius to 10 / cam.z — always 10 screen pixels regardless of zoom level. Applied same fix to edge-click threshold for vertex insertion (16px).
05 Duplicate Flask routes on startup
AssertionError: music_upload endpoint registered twice. Two music API blocks had accumulated in app.py across multiple build sessions, both registering the same route name.
Consolidated all music routes into one clean block. Verified no duplicate @app.route decorators using a Python script that counted route definitions before packaging.
06 Footer appearing mid-page on home
The footer rendered immediately after home page content rather than anchoring to the bottom. Home page had very little content so the footer appeared center-screen.
Made body display:flex; flex-direction:column; min-height:100vh. Each .page.active gets flex:1 to fill remaining space between nav and footer.
07 Free draw: too many raw vertices
Capturing raw mouse points during free-draw produced hundreds of redundant vertices — the resulting polygon was noisy and expensive to render.
Applied Ramer–Douglas–Peucker simplification at 0.4 ft tolerance. Also enforced a minimum point distance (0.3 ft) during capture so slow drawing doesn't over-sample.
08 Species dropdown unreadable in dark sidebar
The native <select> dropdown rendered with transparent background in the dark garden sidebar, making option text invisible against the dark card background.
Set background: #1a2d3d and color: #e2f0fb on the select, option, and optgroup elements explicitly. Native selects inherit these reliably in Chrome/Firefox/Safari.
