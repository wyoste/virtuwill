The Challenge
A business-critical file with no reliable path to the warehouse

The Bigsheet is Greystar's semi-annual revaluation workbook — a months-long, manually authored Excel file that captures actual financial performance and refreshed forecasts across every venture in the portfolio. Getting it from business document to data warehouse had never been solved.

📅

Months of work, weeks more to ingest

After a multi-month revaluation cycle, converting the Bigsheet into a warehouse-ready format historically required several additional weeks of manual file manipulation — data that business teams needed was unavailable long after the source was complete.

⚠️

Data quality was an afterthought

The Bigsheet is built for financial analysis and distribution, not for system ingestion. Merged cells, multi-row headers, fund-level section breaks, embedded formula errors, and mixed data types all had to be manually resolved — with inconsistent results each cycle.

🔁

Repeated loads and double work

DQ issues would surface only after ingestion into DMP, requiring additional rounds of manual manipulation, re-extraction, and re-loading — compounding the delay and eroding confidence in the data among analytics consumers.

⬛ Before — Manual Process

  • Weeks of manual cell-by-cell reformatting after months of reval work
  • No consistent column naming or section boundary detection
  • Float precision errors, embedded newlines, formula error strings left in data
  • Scientific notation vs. decimal notation mismatches discovered post-load
  • DQ issues caught only after warehouse ingestion
  • Multiple reloads required per reval cycle
  • No audit trail linking field-level issues to source cells

✅ After — Automated Tool

  • Conversion in seconds — drop XLSX, click convert, download CSV
  • Consistent, validated column naming across all 127 fields
  • Precision cleaning, newline normalisation, formula errors blanked automatically
  • Full decimal notation — no scientific notation artifacts
  • Cell-level QA before any warehouse load
  • Structured DQ issue export: venture, reval_id, field, source value, converted value
  • Iterative rule refinement loop — issues drive converter improvements
The Solution
A unified Converter & QA Studio

Built iteratively using Claude Code, the tool combines a browser-based XLSX converter with a granular, cell-level QA engine in a single HTML file — no infrastructure, no dependencies, no installs.

Core Capability 1

Bigsheet Converter

Reads the complex fund-structured XLSX directly in the browser using SheetJS. Detects fund section boundaries, parses per-fund header rows, and flattens 1,024 records across 85 fund sections and 127 columns into a clean flat CSV.

Every conversion rule was developed through a test-and-refine cycle against the real source file, ensuring correctness rather than assumption.

Conversion Rules Applied
1

Section boundary detection

Identifies fund name rows ("Revaluation Summary: …") to delimit sections; reads master header rows (rows 10–11) to build the canonical column map across all 85 fund instances.

2

Header normalisation

Applies {SectionName}_{ColumnName} convention; strips quotes; maps %→pct, #→num; collapses whitespace and special characters to underscores.

3

Numeric precision cleaning

Rounds to 15 significant figures to eliminate IEEE 754 binary noise (e.g. 32020746.040000003 → 32020746.04). Always outputs full decimal notation — never scientific notation.

4

Edge case handling

Strips trailing x from multiplier fields; normalises currency prefixes (€2,336,068 → 2336068); blanks formula error strings (#DIV/0!, #VALUE!); converts empty date-formatted cells (serial 0) to blank rather than 1899-12-30.

Core Capability 2

Two-Frame QA Audit

Load the source XLSX and the converted CSV side-by-side. The top frame surfaces a full quality summary — missing records, phantom records, field mismatch counts, and a DQ health chart ranking every field by percentage of clean records.

A resizable drag handle lets you expand either frame. The bottom frame allows fund-level drill-down: select any venture from a dropdown and inspect every field cell-by-cell, with source and converted values shown in-line.

Core Capability 3

Structured DQ Issue Export

Every mismatch — missing record, phantom record, or field-level difference — can be exported as a structured CSV capturing venture, reval_id, identifier, field name, issue category, the converted value, and the original source value.

This export drove the iterative refinement cycle: each issue file was analysed, root causes classified, and converter or comparison rules updated accordingly.

Engineering Depth
Comparison rules built for financial data reality

The QA comparison engine had to handle a wide range of representation differences that are mathematically equivalent but textually distinct — distinguishing genuine data errors from cosmetic format differences.

Design principle: The comparison engine never flags a difference that is cosmetically different but numerically identical. Scientific notation, exponent zero-padding, float precision drift, and multiplier suffix formats are all normalised before comparison. Only genuine value differences surface as issues.

Forward Risk
The structural problem the tool cannot solve alone

⚠ Format Instability Risk

The Bigsheet is a manually authored workbook with no enforced schema. The revals team has changed the file format across prior cycles — adding columns, restructuring sections, or shifting column positions. Each format change breaks the converter's column map and requires reconfiguration. Lack of consistent business processes prevents building once and maintaining; instead, the team faces potential rebuild effort every cycle for what is fundamentally a single-file ingestion.

Recommended mitigation: Establish a data contract with the revals team — a locked column schema, section naming convention, and change-control process for the Bigsheet. The converter can be extended with a schema validation step that detects format drift and alerts before conversion, rather than producing silently incorrect output. The QA Studio's DQ export provides the evidence base to negotiate and enforce that contract.
